# 完整 Web 验收记录

使用 Windows 11、Python 3.14.6、MySQL 8.0.46 和 Microsoft Edge。每次执行从独立数据目录初始化数据库，按顺序加载基础表、虚构案例、Web 认证、仪表盘和业务扩展。应用以独立最小权限账号连接临时实例。课程样例全为虚构身份、链接和内容。

| 登录、账号和角色 | 六类身份、会话过期/撤销、直接 API 访问控制、管理员分配和调整角色、停用和启用账户、最后一个启用的系统管理员保护 |
| 活动、项目与任务 | 创建编辑活动，配置项目审核人，创建照片、排版及剪辑任务；多人分配及实际参与、历史状态、退出人员分配拦截 |

| 视频及按活动三审 | 在 Edge 分配任务、登记实际工作、上传成片、提交部长独剪版；首步交接给主编且部长自审请求被拒绝。主编退回重提后依次经主编、二审、三审，最终由部长发布 |

首次集成发现任期新增后的 `INSERT … SELECT` 与 MySQL 任职触发器在源表上的锁冲突。改用同一事务中的独立查询和 `INSERT … VALUES`，复测通过。浏览器验收对照数据库状态、真实下载响应和界面反馈。

## 2026-11-23 工时、发布和工作台复测

在全新临时 MySQL 实例载入包含既有工时、审核、发布记录的基础案例，然后应用扩展 11 至 14。52 项基础断言通过，33 项 Web 与数据库集成测试全部通过，用时 32.71 秒。[执行记录](web_evidence/workflow-tests.log) · [工作台截图](web_evidence/workflow-inbox.png)

| 场景 | 测试操作和预期结果 |
| --- | --- |
| 读书节推文改派 | 撰稿员误登排版工时 20 分钟，部长结束分配并指派排版员。排版员遇到冲突能看到记录号和分钟数，并打开实际参与列表。部长填原因作废，排版员登记 30 分钟后在 Edge 成功提交秀米版，部长从首页直达该版并初审。 |
| 纠错权限和审计 | 部员操作返回 403，空原因返回 400。两个负责人会话并发作废同一笔时只有一个成功。原登记人、作废人、原因和原分钟数可查询，撰稿员的统计恢复到误登记前的值。已发布后的统计订正保留发布记录及任务结项历史。 |
| 主编登记发布 | 终审前提前发布回滚任务状态和修订号。终审后，部长的页面、API 和数据库过程均受到权限检查。主编从首页进入指定推文，填写公众号渠道和链接后发布。必做任务同步完成，发布人是主编，同活动视频仍待处理，活动完成率为 50%。 |
| 真实业务阻塞 | 有必做任务缺少工时或处于受阻状态时，主编看到具体任务名。补足工时、解除阻塞后可正常发布。成功后重复提交被拒绝。 |
| 工作台入口 | 验证单条待审及待处理的数字卡片，审核及转交列表，排版员的退回重提、微信草稿入口，以及主编的发布待办。 |

新增数据库对象的可执行 SQL 和预期值在 `test_workflow_migration_archive_constraints_and_publisher_view` 中。该用例用隔离维护账号验证下列对象，并用 Web 数据库账号核实归档表的写权限。[测试源码](../tests/test_web_operations.py)

| 数据库对象 | 核对方法与预期结果 |
| --- | --- |
| `v_project_publishers` | 按推文项目查询发布人，结果为该项目指定的在任主编。事务中关闭其主编任期后结果为空，回滚恢复原数据。 |
| `voided_work_contribution` 主键、外键和索引 | 查询 `information_schema.key_column_usage` 和 `SHOW INDEX FROM voided_work_contribution`。原记录 ID 是唯一主键，任务、成员任期、原登记人和作废人各有外键及索引。尝试重复 ID 返回 1062，四个外键分别传入不存在的 ID 均被拒绝。 |
| 分钟数与原因检查 | 分别传入零分钟和纯空格原因，预期 MySQL 返回 3819。Web 账号直接更新或删除归档行会被拒绝。 |
