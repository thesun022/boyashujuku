# 山大博雅传媒中心综合业务管理系统数据库设计

目标为 MySQL 8.0.16+，字符集 utf8mb4，排序规则 utf8mb4_0900_ai_ci，存储引擎 InnoDB。时间字段以北京时间录入和展示，日期使用左闭右开区间。

## 对原 27 张表的审查结论

保留原 27 张业务实体，增加 `cohort` 和 `project_review_route`，最终 29 张。届次名称由 `cohort` 统一维护。同一个人可拥有多条履历，职务分段挂在具体任期。审核人是项目和人员之间按审核级别确定的关系，单独建表可以支持外部老师及不同项目的审核人员。

## 业务键及范式

- 多对多关系通过任职、技能、角色授权、角色权限、人员指派、贡献、项目素材和提交素材等表表示。审核名单的键是项目和审核级别。
- 每列保存一个标量。桥表属性依赖对应业务关系的完整键；例如提交素材关系依赖版本和素材，审核结论依赖版本与级别。人员名、届次名、权限名等各由对应主表维护。
- 项目进度、当前成员、相机当前状态及工作量合计从事实推导。二审通过时保存的三审快照是该版本历史事实。生成列用来实现只约束开放记录的唯一键。工作状态历史与审计日志记录历史事件。
- 除另有说明，业务外键限制删除，历史资料通过结束任期、停用账号、完成或取消状态管理。

## 完整性与事务分工

- 主键、外键、唯一约束和 CHECK 承担单行、关联键和明确唯一性的规则。日期重叠、限额、防自审和必要审核由事务及触发器处理。
- 触发器负责成员任期重叠及退出、工作状态历史和发布下限等与写入密切相关的约束。存储过程负责审核交接、版本切换、人员分配、相机预约及工作状态的完整事务。
- 项目工作状态使用 `lock_version` 比较并更新。审核以项目为串行化单位。相机写入先锁设备行，再检查时间冲突。触发器及过程使用当前读或在持锁后于 READ COMMITTED 读取。
- 后续应用只调用带参数的查询或过程，并从已验证的身份绑定操作者。账号使用 Argon2id 编码哈希；验证密码在未来应用认证层完成。SQL 业务角色与业务 RBAC 分离，部署账户管理基础字典，业务写账户按授权调用过程。部署和恢复细节见数据库目录。

## 状态字典

| 对象 | 状态或事件 |
| --- | --- |
| 成员 | ACTIVE、EXITED。按任期结束时间推导 |
| 工作 | TODO、IN_PROGRESS、BLOCKED、DONE、CANCELLED |
| 项目 | PLANNED、IN_PROGRESS、IN_REVIEW、RETURNED、READY_TO_PUBLISH、COMPLETED、PUBLISHED |
| 成果 | XIUMI、WECHAT、VIDEO、GENERIC；状态由最新交接和发布事实推导 |
| 审核级别 | MINISTER、CHIEF、SECOND、THIRD |
| 审核结论 | APPROVED、RETURNED |
| 交接目的 | MINISTER、CHIEF、SECOND、THIRD、REWORK、WECHAT_DRAFT、PUBLISH |
| 相机 | AVAILABLE、MAINTENANCE、RETIRED 为设备可用性；预约、在用和逾期按使用记录判断 |
